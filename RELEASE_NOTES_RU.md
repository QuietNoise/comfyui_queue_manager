# Release Notes — ComfyUI Queue Manager

## Сводка Merge Request

Данный Merge Request представляет собой значительную эволюцию ComfyUI Queue Manager — от базовой персистентной очереди с возможностью паузы/возобновления и архивирования до **полнофункциональной многоэтапной системы управления очередью** с категоризацией, тегированием, перетаскиванием элементов, массовыми операциями и настраиваемыми параметрами пользователя.

Ниже приведён подробный список всех изменений по сравнению с исходной версией (описанной в оригинальном `README.md`).

---

## 1. Система категоризации очереди (многоэтапный workflow)

**До:** Все новые задачи попадали напрямую в очередь ожидания (status=0) и выполнялись в порядке FIFO.

**После:** Новые задачи проходят **многоэтапный конвейер**:

| Этап | Статус | Описание |
|------|--------|----------|
| **New** | 4 | Только что поставленные в очередь задачи, ожидающие категоризации |
| **Priority** | 5 | Задачи высокого приоритета |
| **Main** | 6 | Стандартные задачи |
| **Background** | 7 | Задачи низкого приоритета |
| **Pending** | 0 | Готовы к выполнению (после Build Queue) |
| **Running** | 1 | Выполняются в данный момент |
| **Completed** | 2 | Успешно завершены |
| **Archived** | 3 | Сохранены для последующего запуска |

**Новые вкладки интерфейса:**
- **New** — показывает некатегоризированные задачи (status=4). Для каждого элемента доступны кнопки перемещения в Priority/Main/Background.
- **Waiting** — показывает все категоризированные задачи (status 5/6/7) с фильтрами-переключателями для каждой категории.
- **Queue** — показывает задачи, готовые к выполнению (status=0).
- **Archive** — сохранённые задачи (status=3).
- **Completed** — завершённые задачи (status=2).
- **Settings** — настраиваемые параметры пользователя.

**Кнопка Build Queue:**
Новая кнопка "Build Queue" управляет многоэтапным конвейером по следующему двухфазному алгоритму:

**Фаза 1 — Архивация:** Все текущие ожидающие элементы (status=0) архивируются (status=3) с сохранением их существующих тегов.

**Фаза 2 — Обработка уровней приоритета по порядку (Priority → Main → Background):**
Для каждого уровня выполняются два подшага:
- **Подшаг A:** Элементы из категории (status 5/6/7) перемещаются в ожидание (status=0) — они попадают в **начало** очереди выполнения, упорядоченные по `updated_at` внутри своего уровня.
- **Подшаг B:** Элементы из архива (status=3) с **соответствующим тегом** перемещаются в ожидание (status=0) — они попадают **после** элементов из категории, также упорядоченные по `updated_at`.

Результат — очередь, собранная в строгом порядке приоритетов:
```
[Priority из категории] → [Priority из архива] → [Main из категории] → [Main из архива] → [Background из категории] → [Background из архива]
```

После выполнения Build Queue в архиве (status=3) остаются только элементы с неприоритетными тегами (`archive`, `none`, `new`, `completed`). Все элементы с тегами `priority`, `main` или `background` перемещаются в очередь выполнения.

Это позволяет пользователям ставить в очередь множество workflow, категоризировать их по важности, а затем собирать очередь выполнения в контролируемом и предсказуемом порядке.

## 2. Система тегов

**До:** Механизм тегирования отсутствовал.

**После:** Каждый элемент очереди теперь имеет поле `tag` с валидацией:

```python
VALID_TAGS = {"none", "new", "main", "priority", "background", "archive", "completed"}
```

- Теги автоматически синхронизируются с изменениями статуса.
- **Критическое исправление:** Операции архивирования теперь **сохраняют существующие теги** вместо их перезаписи. Это означает, что категоризированные элементы (priority/main/background) сохраняют свой тег категории даже при архивировании, что позволяет алгоритму Build Queue корректно восстанавливать их.
- Теги отображаются в виде интуитивно понятных SVG-иконок (флажок для priority, домик для main, квадрат для background).
- Новый API-эндпоинт: `POST /queue_manager/tag` для обновления тегов.

## 3. Перетаскивание элементов (Drag-and-Drop)

**До:** Порядок выполнения очереди был фиксированным (FIFO по времени добавления).

**После:** Пользователи могут изменять порядок ожидающих элементов очереди с помощью перетаскивания мышью.

- **Библиотека:** `@dnd-kit/core` + `@dnd-kit/sortable` (совместимо с React 19).
- **Механизм:** Ручки перетаскивания появляются на вкладке "Queue". Когда элемент бросается на новую позицию, бэкенд перераспределяет существующие значения `number` среди переупорядоченных элементов — это гарантирует, что элементы на других страницах не затрагиваются.
- **Оптимистичный UI:** Фронтенд обновляется немедленно, затем сохраняет изменения на бэкенде.
- **Новый API-эндпоинт:** `POST /queue_manager/reorder`
- **Новый метод бэкенда:** `QM_Queue.reorder_items()`

## 4. Массовое выделение и операции

**До:** Действия (архивирование, удаление, экспорт) применялись либо ко всем элементам, либо только к отдельным.

**После:** Флажки позволяют массово выделять элементы на вкладках Queue, New, Archive и Waiting.

- Выделить все / снять выделение через флажок в заголовке.
- Массовое перемещение выделенных элементов в категории Priority/Main/Background.
- Состояние выделения синхронизируется с нижней панелью через `AppContext`, что позволяет отображать кнопки массовых действий.
- Выделение сбрасывается при изменении данных.

## 5. Страница настроек

**До:** Всё поведение было жёстко закодировано (как отмечено в оригинальном Roadmap: "Options. Toggles, big red buttons, levers and valves to control Queue Manager's behavior. Now everything is hardcoded.")

**После:** Новая вкладка **Settings** позволяет пользователям настраивать:

- **Статус по умолчанию для новых задач** — выбор, куда попадают новые задачи (pending, new, priority, main, background).
- **Тег по умолчанию для новых задач** — выбор тега по умолчанию (priority, main, background, archive).

**Новые API-эндпоинты:**
- `GET /queue_manager/settings` — получение текущих настроек.
- `POST /queue_manager/settings` — сохранение настроек с валидацией.

**Бэкенд:** Метод `QM_Options.get()` улучшен для обработки кэшированных значений с поддержкой временных меток.

## 6. Улучшения UI/UX

### 6.1 Иконки вкладок навигации
Каждая вкладка теперь имеет distinct-иконку Lucide для визуальной ясности:
- Queue: иконка `List`
- New: иконка `Sparkles`
- Waiting: иконка `Clock`
- Archive: иконка `Archive`
- Completed: иконка `CheckCircle`
- Settings: иконка `Settings`

### 6.2 Индикаторы загрузки
Кнопки вкладок показывают вращающуюся иконку обновления во время загрузки данных, обеспечивая визуальную обратную связь при асинхронных операциях. Отслеживание ID запроса предотвращает использование устаревших данных при быстром переключении вкладок.

### 6.3 Улучшенная пагинация
Интерфейс пагинации теперь:
- Динамически обрабатывает различное количество страниц.
- Использует умное размещение многоточий (`…`) для сохранения консистентности UI.
- Показывает правильные отступы и визуальные индикаторы для пропусков страниц.

### 6.4 Фильтры-переключатели категорий (вкладка Waiting)
Интерфейс фильтрации на вкладке Waiting был переработан с флажков на **кнопки-переключатели**, которые одновременно управляют фильтрами статуса и тега. Выбор/отмена категории применяет фильтры немедленно, без отдельной кнопки "Apply".

### 6.5 Подсказки и иконки
- Все кнопки действий теперь имеют атрибуты `title` для всплывающих подсказок.
- Индикаторы статуса (priority/main/background) используют SVG-иконки вместо текстовых меток.
- Единый стиль иконок во всех компонентах очереди.

### 6.6 Тёмная тема
Добавлены стили тёмной темы для вкладок навигации (классы `dark:bg-neutral-800 bg-neutral-200 active`).

## 7. Улучшения качества кода и архитектуры

### 7.1 Рефакторинг Build Queue
Метод `build_queue()` был разделён на два отдельных этапа:
- `_build_queue_step1_archive_pending()` — архивирует текущие ожидающие элементы.
- `_build_queue_step2_process_tiers()` — обрабатывает уровни приоритетов (категория + архив с соответствующими тегами).

Это улучшает читаемость, тестируемость и детализацию логирования.

### 7.2 Оптимизация производительности
- `fetchQueueItems()` преобразован в `useCallback` для предотвращения лишних повторных рендеров.
- Логика фильтров и маршрутов вынесена в переиспользуемые хуки `useCallback`.
- Правильное управление зависимостями в хуках `useEffect`.
- Отслеживание ID запроса предотвращает использование устаревших ответов при быстром переключении вкладок.

### 7.3 Сохранение тегов при архивировании (исправление ошибки)
Два коммита (`43fc731`, `2b3ca8c`) исправили критическую ошибку, при которой архивирование элементов перезаписывало их существующие теги. Теперь `archive_queue()` и `archive_items()` изменяют только статус на 3, не модифицируя поле тега.

### 7.4 Упрощение типов очереди
Отдельные типы очереди priority/main/background были удалены из UI, так как они стали избыточными после внедрения новой системы статусов ожидания. Значения статусов (5/6/7) остаются в схеме базы данных для системы категоризации.

## 10. Обратная совместимость

- **База данных:** Миграция не требуется. Существующие задачи со status=0 продолжают работать. Колонка `tag` добавляется через `ALTER TABLE`, если отсутствует.
- **API:** Все существующие эндпоинты остаются функциональными. Новые маршруты являются аддитивными.
- **UI:** Оригинальные вкладки Queue, Archive и Completed работают идентично прежнему. Новые вкладки являются аддитивными.
- **Внешние задания:** Без изменений — они по-прежнему обходят Queue Manager и направляются напрямую в нативную очередь.

## Резюме

Данный Merge Request превращает ComfyUI Queue Manager из базового инструмента персистентности очереди в **профессиональную систему управления очередью** с:

- Многоэтапной категоризацией (New → Priority/Main/Background → Pending → Execution)
- Визуальным перетаскиванием элементов
- Массовыми операциями с выделением
- Настраиваемыми параметрами пользователя
- Богатым UI с иконками, подсказками и индикаторами загрузки
- Надёжной системой тегов с сохранением при архивировании
- Комплексной документацией и инструментарием для разработки

Пункты оригинального Roadmap для "Options" и "Better user and dev docs" были реализованы. Оставшиеся пункты (Bin, Cover images, More columns) оставлены для будущих итераций.
